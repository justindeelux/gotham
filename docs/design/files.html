Right-clicking a row opens its menu at the cursor; on an unselected row it selects that row first, on a row already inside the selection it keeps the whole multi-selection. Shift+F10 (or the menu key) opens the same menu on the focused row. A folder row also offers Paste, which pastes the clipboard INTO that folder; a file row has no destination, so it has no Paste. Disabled actions follow the write gate (a read-only root greys every write action), and a special file opens no menu.

Right-click empty space for the folder menu:

Keyboard: ↑ ↓ move, Enter open, ⌘/Ctrl+click multi-select, F2 rename, Del delete — all scoped to the focused list, never to the editor.

Recycle bin

per root · restore to the recorded path · purge one · empty

Deleting an entry now moves it into the root's recycle bin instead of removing it. The bin is per root: .gotham-trash holds each deleted entry with its original path, deleted-at, size and kind. Any team member can list the bin; restoring, permanently deleting one entry and emptying the bin need owner or admin on a writable root.

The delete confirm always moves entries to the recycle bin (Move to recycle bin) — a normal delete is never permanent. Permanent deletion happens only from the bin: purge a single entry or empty the whole bin. A restore that meets an existing entry at the original path returns 409 and shows a clear conflict message — nothing is overwritten. A capped listing says it is truncated; entries have no auto-expiry in v1.

Editor window

floating window · minimize → bottom dock · tabs, dirty dot, conflict-safe saves

Opening a file renders it in a floating window pinned bottom-right. Esc (or the minimize control) folds it into an app-dock bar along the bottom of the content column; the dock item — file name plus an unsaved dot — restores it, and clicking another file in the browser restores it too. Buffers, dirty state, open tabs and conflict dialogs survive minimize/restore. Multiple files still use the window's tabs.
