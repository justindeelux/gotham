Dump tool phụ thuộc engine và chạy trong container tạm

Control plane không cài sẵn công cụ dump trên node. Mỗi job backup tạo một container dùng đúng image của engine (postgres:16-alpine, mysql:8.0, mongo:7, redis:7-alpine), gắn volume của database rồi chạy pg_dump / mysqldump / mongodump / copy RDB-AOF. Container bị xoá ngay sau khi bản dump được nén và đẩy lên đích lưu trữ.

Tạo database

Chọn engine → cấu hình volume, credentials và backup → xác nhận. Container được tạo trên node qua agent gRPC.

Healthcheck và port lấy từ spec của engine. Volume luôn tách khỏi vòng đời container.

Engine

Tag image = engine + phiên bản, ví dụ postgres:16-alpine.
Container tạo qua agent trên node này; backup cũng chạy tại đây.

Cấu hình database

Dùng cho container gotham-db-{tên}. Tên không hợp lệ: 3–31 ký tự, bắt đầu bằng chữ cái, chỉ a-z, 0-9 và dấu gạch ngang.
Lưu trong bảng secrets, mã hoá AES-256-GCM.

Bật public access

Mặc định database chỉ nằm trong network nội bộ. Bật để Traefik mở một cổng ra internet cho client bên ngoài.

Public port là bề mặt tấn công

Cổng sẽ được mở trên node và không giới hạn IP nguồn. Chỉ bật khi client bắt buộc, dùng mật khẩu mạnh và xoay vòng định kỳ — hoặc để trống và truy cập qua network nội bộ.

Docker volume gotham-db-{id} được mount vào đây và giữ lại 7 ngày sau khi xoá database.

Bật backup hằng ngày

Job chạy trong container tạm, nén rồi đẩy lên đích S3 đã cấu hình.
